# Tempo — Lottie animations

Character/celebration animations rendered via `lottie-react-native`
(`components/TempoLottie.tsx`) — distinct from the app's existing hand-built
`Animated`+SVG primitives (`SvgProgressRing`, `TempoPulse`, `celebration.tsx`'s
`ConfettiBurst`), which stay exactly as they are.

## Tempo Coach (`coach/*.json`)

The blue runner from the app icon (`brand-assets/app-icon-512.png`), extended
into a small pose library from the founder's reference sheet
(`brand-assets/tempo-coach-reference-sheet.jpeg`) and traced into real vector
Lottie shapes (not embedded raster images) — crisp at any size, tiny file size
(4-6KB each), no JPEG artifacts. `brand-assets/coach-poses/*.png` are the
cleaned (background-removed) source crops the traces were built from, kept for
provenance/future re-tracing.

**Why vector, not the raster crop:** an early version of this embedded the
cropped PNG directly in the Lottie file. The founder correctly flagged that
animating a raster image doesn't fix a soft/low-res source — motion can't add
resolution. The fix was tracing the flat-color silhouettes into actual vector
paths (`skimage.measure.find_contours` + Douglas-Peucker simplification +
Catmull-Rom tangent smoothing for round edges), which renders sharp at any
scale and incidentally cleans up the JPEG compression noise along the edges.

All 8 traced poses are wired in somewhere:

| File | Pose | Style | Wired into |
|---|---|---|---|
| `sprinting.json` | mid-run (matches the app icon) | `bob` loop | `FocusMode.tsx` — badge above the rest ring while resting |
| `wave.json` | waving hello | `bob` loop | `sign-in.tsx` — in the gap between the logo and the wordmark (moved there from directly above the logo once the founder pointed out the dead space) |
| `pointing.json` | arm raised, pointing | `bob` loop | `onboarding/why-tempo.tsx` — beside the calendar animation |
| `highfive.json` | two hands high-fiving | `pop` (plays once) | `workout-complete.tsx` — the default celebration (PR/achievement/routine tiers), alongside the existing confetti |
| `jumpjack.json` | jumping jack | `pop` (plays once) | `workout-complete.tsx` — swapped in specifically for the `levelup` tier, the biggest moment on that screen |
| `idle.json` | standing | `bob` loop | `(tabs)/plan.tsx` — beside the "No split yet" empty state |
| `walking.json` | walking | `bob` loop | `quick-workout.tsx` — above "How much time do you have?" |
| `pondering.json` | hand on chin, thinking | `bob` loop | `onboarding/plan-preview.tsx` — above the ring on the "Personalizing your plan…" generating screen |

**Two animation styles**, both generated by the same script (see below):
- `bob` — a continuous, seamless idle loop (gentle vertical bob + slight
  rotation sway). Frame 0 and the last frame are identical, so `loop={true}`
  never stutters.
- `pop` — a one-shot scale-up entrance with a small overshoot, then holds.
  Use with `loop={false}`.

**Regenerating or adding a pose:** the trace/generate script lives in this
session's scratchpad, not the repo (it's a build-time tool, not app code) —
the short version: isolate the pose on transparent background (color-distance
+ connected-component filtering to strip stray marks), trace with
`skimage.measure.find_contours`, simplify with
`skimage.measure.approximate_polygon`, add Catmull-Rom tangent smoothing per
vertex, emit a bodymovin shape layer, wrap in either the `bob` or `pop`
transform template. If this needs rebuilding from a new reference sheet, ask
for the pipeline to be recreated — the technique is documented above.

## Other files

- **`LottieLogo1.json`** — the official example animation bundled with the
  `lottie-react-native` library's own demo app (from
  `github.com/lottie-react-native/lottie-react-native`, `example/animations/`,
  Apache License 2.0 — same repo and license as the `lottie-react-native`
  dependency itself). A real, complex (48 layers, ~6s), known-good file.
  **Not wired into any screen** — it's a test fixture only, useful for the
  on-device pass: if something renders wrong, swapping a screen's coach file
  for this one for a minute tells you whether the problem is
  `lottie-react-native`'s native setup (this would also fail) or specifically
  one of the traced `coach/*.json` files (this would render fine, they
  wouldn't). Delete it once you no longer need that isolation check.

## Recoloring a free (non-Tempo-Coach) asset

If you source something else from LottieFiles' free tier that isn't already
Tempo blue: recoloring doesn't need their paid recolor tool —
`lottie-react-native`'s own `colorFilters` prop (free, part of the library)
recolors by layer keypath:
```tsx
<TempoLottie
  source={require('@/assets/lottie/yourFile.json')}
  colorFilters={[{ keypath: 'Layer Name', color: '#4E8BFF' }]}
/>
```
Find each layer's keypath in LottieFiles' free online preview (the Layers
panel lists every layer name), or by opening the JSON and reading each
layer's `"nm"` field. (The `coach/*.json` files don't need this — they're
already Tempo blue by construction.)
